# Эпик E2 — RAG / База знаний

**Цель:** подключить базу знаний компании к ИИ: индексация документов, семантический поиск, сборка контекста.
**Можно стартовать:** сразу (по контракту §3).
**Milestone:** M2.

## Задачи
1. FastAPI-сервис, реализующий контракт §3 ([`../03-interfaces.md`](../03-interfaces.md)).
2. Пайплайн ингеста (решение D5) для трёх источников:
   - **Веб-сайт** — краулер (учитывает robots.txt), извлечение основного контента, дедупликация.
   - **Word (.docx)** — парсинг текста и структуры (заголовки/таблицы).
   - **PDF** — извлечение текста; для сканов — опциональный OCR (уточнить, есть ли сканы).
   Далее: очистка, чанкование, метаданные (`source`, `title`, `url/filename`, `lang`, `updated_at`).
3. Эмбеддинги (OpenAI embeddings или локальные), запись в Vector DB (Qdrant/pgvector).
4. Поиск: `POST /v1/search` с `top_k`, фильтрами по источнику/языку, реранкингом (опционально).
5. Обновление/удаление документов, переиндексация, версии базы знаний.
6. Поддержка нескольких языков (RU/KY/EN — уточнить, см. открытые вопросы).
7. Оценочный набор: список вопросов и ожидаемых источников, метрики recall@k / hit-rate.
8. Тесты: unit (чанкование), контрактные (search/ingest), качество на оценочном наборе.

## Критерии приёмки (M2)
- Индексирует тестовую базу знаний.
- `POST /v1/search` возвращает релевантные фрагменты, recall@5 ≥ цели.
- Обновление/удаление документов работает.

## Зависимости / контракты
- Потребляет: Vector DB (E0), исходные документы базы знаний (от заказчика).
- Производит: Search API — потребляет LLM Gateway (E1).

## Открытые входные данные
- Доступ к сайту (карта URL/sitemap) и набор файлов Word/PDF от заказчика.
- Есть ли среди PDF сканы (нужен ли OCR).
