# Эпик E5 — Интеграция с CRM

**Цель:** двусторонняя синхронизация ИИ-платформы с CRM для сквозного контроля сделок и авто-фиксации метрик.
**Можно стартовать:** сразу против `mock-crm` по адаптерному интерфейсу.
**Milestone:** M6.
**Статус:** ✅ реализованы адаптеры amoCRM (OAuth + refresh) и Bitrix24 (REST-вебхук), дедуп по телефону, маппинг этапов, события (slog). TODO: персист событий в БД.

> Решение D1 ([`../06-decisions.md`](../06-decisions.md)): поддерживаем **обе** CRM — **amoCRM и Bitrix24** —
> за единым адаптерным интерфейсом. Выбор через `CRM_PROVIDER=amocrm|bitrix24`.

## Задачи
1. Реализовать **два адаптера** по интерфейсу §4 ([`../03-interfaces.md`](../03-interfaces.md)):
   - **amoCRM** — OAuth 2.0, REST API, вебхуки (лиды/сделки/воронки).
   - **Bitrix24** — REST API (вебхуки/локальное приложение); учесть коробочную (on-prem) версию для резиденции данных в КГ.
2. Аутентификация (OAuth/API-ключ), хранение и обновление токенов — для каждой CRM.
3. Маппинг сущностей **отдельно для каждой CRM**: контакт, лид, сделка, задача, заметка, статусы/этапы воронки.
4. Операции: upsert контакта/лида, обновление этапа сделки, создание задачи, добавление заметки, поиск по телефону.
5. Входящие изменения из CRM → `POST /webhooks/crm` → n8n (двусторонняя синхронизация).
6. Идемпотентность и дедупликация (поиск по телефону/внешнему id).
7. Запись событий `lead_created` / `deal_stage_changed` в `events`.
8. Тесты: контрактные против `mock-crm` + интеграционные на тестовых порталах **amoCRM и Bitrix24**.

## Критерии приёмки (M6)
- Лид из чата автоматически создаётся в CRM, дубликаты не плодятся.
- Изменения этапов сделок синхронизируются в обе стороны.
- События пишутся в аналитику.

## Зависимости / контракты
- Потребляет: выбранную CRM, n8n (E4).
- Производит: CRM-операции по адаптерному интерфейсу.
