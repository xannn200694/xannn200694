# Эпик E6 — Аналитика и дашборды

**Цель:** прозрачная сквозная аналитика по лидам, ответам и сделкам на основе единого журнала событий.
**Можно стартовать:** сразу (на сгенерированных событиях по схеме §5).
**Milestone:** M7.
**Статус:** ✅ реализованы SQL-витрины (TTFR, lead capture, automation/escalation, воронка, объём), сид демо-данных, описание дашбордов Metabase. Проверено на PostgreSQL 16.

## Задачи
1. Закрепить схему событий §5 ([`../03-interfaces.md`](../03-interfaces.md)) и таблицу `events`.
2. Витрины/материализованные представления: воронка, время ответа, конверсии, нагрузка бот vs. человек.
3. Развернуть Metabase (или Grafana) из E0, подключить к PostgreSQL.
4. Дашборды KPI:
   - TTFR (медиана, p95), динамика по дням/часам.
   - Lead capture rate, число лидов по каналам/источникам.
   - Automation rate vs. escalation rate.
   - Answer quality (из оценочного набора E2/E1).
   - Воронка: лид → квалифицированный → сделка → выигрыш.
5. Генератор тестовых событий для разработки дашбордов без реальных данных.
6. Экспорт дефиниций дашбордов в репозиторий, где возможно.
7. Алерты по аномалиям (рост escalation rate, падение capture rate) — совместно с E7.

## Критерии приёмки (M7)
- Дашборд отображает все ключевые KPI на реальных/тестовых данных.
- Метрики считаются корректно (сверка на контрольном наборе).

## Зависимости / контракты
- Потребляет: таблицу `events` (все эпики пишут туда).
- Производит: дашборды и витрины KPI.
