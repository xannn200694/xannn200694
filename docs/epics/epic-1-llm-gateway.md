# Эпик E1 — LLM Gateway (промпты + OpenAI/Claude)

**Цель:** единая точка доступа к LLM с управлением промптами, выбором модели, логикой эскалации и учётом стоимости.
**Можно стартовать:** сразу против `mock-rag`.
**Milestone:** M1.

## Задачи
1. FastAPI-сервис, реализующий контракт §2 ([`../03-interfaces.md`](../03-interfaces.md)).
2. Абстракция провайдера LLM: адаптеры OpenAI и Anthropic (Claude), единый интерфейс, переключение по `model`.
3. Управление промптами: хранение в БД (`prompts`), версионирование, шаблонизация (Jinja2), endpoint списка/получения.
4. Сборка контекста: вызов RAG `POST /v1/search`, вставка `kb_context` и истории диалога.
5. Логика `should_escalate` и `confidence` (низкая уверенность, явный запрос человека, стоп-темы).
6. `POST /v1/classify` — намерение и lead_score для квалификации.
7. Учёт токенов и стоимости (`usage`), запись события `llm_call` в `events`.
8. Защита: rate limiting, таймауты, ретраи, fallback на резервную модель.
9. Тесты: unit (адаптеры, шаблоны), контрактные (схемы запрос/ответ), оценочный набор промптов.

## Системные промпты (черновой набор)
- Базовый ассистент отдела продаж (тон, язык, границы, «не выдумывай — используй контекст»).
- Промпт квалификации лида.
- Промпт эскалации/сбора контактов.

## Критерии приёмки (M1)
- `POST /v1/chat` отвечает, переключение моделей работает.
- Версии промптов применяются и доступны через API.
- Эскалация и confidence работают на тестовых кейсах.
- Учёт токенов/стоимости пишется в `events`.

## Зависимости / контракты
- Потребляет: RAG API (§3), таблицы `prompts`/`events`.
- Производит: Chat/Classify API — потребляет n8n (E4) и каналы (E3).
