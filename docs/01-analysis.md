# 01. Анализ вакансии и постановка задачи

## Источник

- **Вакансия:** AI Automation Engineer / ИИ-Интегратор (Отдел продаж)
- **Компания:** K-Technology (ОсОО «Бизнес-процессы»), Бишкек, Кыргызстан
- **Формат:** проектная работа (project-based), оплата по этапам (Back-to-Back Milestone Payments)
- **Суть:** ИТ-компания создаёт AI-решения для отделов продаж и ищет инженера, который соберёт
  работающие ИИ-механизмы из готовых API и no-code инструментов.

## Боли бизнеса (из текста вакансии)

1. **Потеря входящих заявок и медленные ответы клиентам.**
2. **Ручная рутинная работа менеджеров и хаос в процессах воронки.**
3. **Отсутствие прозрачной аналитики и сквозного контроля за сделками.**

## Что нужно сделать (обязанности → задачи проекта)

| Обязанность из вакансии | Задача проекта |
|--------------------------|----------------|
| Умные AI-чат-боты для WhatsApp/Telegram, отвечающие 24/7 по базе знаний | Каналы + LLM + RAG (E1, E2, E3) |
| Автоматизация сценариев воронки (n8n, Make) | Оркестрация воркфлоу (E4) |
| Интеграция ИИ с CRM и БД, авто-фиксация метрик | CRM-коннектор + аналитика (E5, E6) |
| Системные промпты, подключение LLM (OpenAI/Claude) по API, калибровка | LLM Gateway + управление промптами (E1) |

## Требования к исполнителю (определяют стек)

- Платформы автоматизации — **n8n** (предпочтительно) или **Make/Integromat**.
- Понимание **LLM**, базовый **prompt-engineering**, настройка **RAG** (подключение баз знаний).
- Интеграция мессенджеров, ИИ-сервисов и **CRM** по **API**.
- **Python** для кастомных интеграций — плюс (не жёсткое требование).

## Цели проекта (SMART-формулировки)

1. **Скорость ответа:** первичный автоответ новому лиду в WhatsApp/Telegram < 5 секунд, 24/7.
2. **Покрытие лидов:** 100% входящих заявок фиксируются и получают ответ (0 «потерянных» лидов).
3. **Качество ответов:** ≥ 80% ответов бота по базе знаний оцениваются как корректные (offline-оценка);
   корректная эскалация на менеджера при низкой уверенности.
4. **Автоматизация рутины:** ключевые шаги воронки (квалификация, постановка задач, напоминания,
   обновление статуса сделки) выполняются автоматически без участия менеджера.
5. **Сквозная аналитика:** дашборд с воронкой, источниками лидов, временем ответа, конверсиями,
   нагрузкой на бота vs. эскалациями.

## Метрики успеха (KPI)

- **TTFR** (Time To First Response) — медиана и p95.
- **Lead capture rate** — доля заявок, попавших в CRM.
- **Automation rate** — доля диалогов, закрытых без человека.
- **Containment / escalation rate** — доля эскалаций на менеджера.
- **Answer quality** — точность ответов RAG-бота на наборе тестовых вопросов.
- **Conversion** — лид → квалифицированный лид → сделка.

## Границы проекта (Scope)

### В объёме (In scope)
- Подключение каналов WhatsApp и Telegram (входящие/исходящие сообщения).
- AI-ассистент с ответами по базе знаний (RAG), эскалация на оператора.
- Автоматизация сценариев воронки в n8n.
- Двусторонняя интеграция с одной CRM (контакт/лид/сделка/задача).
- Сбор событий и аналитический дашборд.
- Среда запуска (Docker), секреты, базовая наблюдаемость, тесты.

### Вне объёма на первом этапе (Out of scope, по умолчанию)
- Голосовые звонки/телефония, распознавание речи.
- Биллинг/оплата внутри чата.
- Мобильное приложение для менеджеров.
- Глубокое обучение/файнтюнинг собственных моделей (используем готовые LLM по API).
- Мультитенантность / коробочный SaaS-продукт (это «перспектива», см. вакансию).

> Эти границы — допущения; их нужно подтвердить (см. [`05-open-questions.md`](05-open-questions.md)).

## Соответствие модели оплаты заказчика

Заказчик платит по контрольным точкам (milestone) за проверенный результат. Поэтому план разбит
на **эпики → milestones**, каждый из которых имеет измеримый критерий приёмки и может быть
сдан/оплачен независимо. См. [`04-parallel-plan.md`](04-parallel-plan.md).
